# Credit Card Fraud Detection Pipeline

End-to-end Machine Learning project for highly imbalanced credit-card fraud
classification.

Implemented models:

- Logistic Regression
- K-Nearest Neighbors (KNN)
- Decision Tree
- **Bonus: Simple MLP implemented with PyTorch**

Implemented optional service:

- **FastAPI `POST /predict` REST endpoint**

> **Important:** The real `data/creditcard.csv` dataset is intentionally
> not committed to Git because of its size. Download it from the Kaggle link in
> the Dataset section and place it locally at `data/creditcard.csv` before
> retraining. The reported metrics were generated from an actual run on the real
> dataset. The trained artifacts `model.pkl`, `scaler.pkl`, and `encoder.pkl`
> are retained in this repository so the trained inference pipeline can be tested
> without retraining.

## 1. Problem Description

### Business Scenario

A bank or payment provider wants to identify potentially fraudulent credit-card
transactions.

```text
0 = Legitimate Transaction
1 = Fraudulent Transaction
```

The central challenge is severe class imbalance. A model can obtain high
Accuracy while still missing many fraud cases.

### Objective

Build a reliable ML pipeline that compares multiple models while analyzing:

- Accuracy
- Precision
- Recall
- F1-score
- Confusion Matrix
- False Positives (FP)
- False Negatives (FN)
- cross-validation stability
- overfitting
- threshold trade-offs

Accuracy is reported, but it is **not** the primary selection metric.

### Dataset

This project uses the **Credit Card Fraud Detection Dataset** from Kaggle:

**Dataset link:**  
https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud

The real dataset file is intentionally **not committed to this repository**
because of its size.

After cloning the repository, download `creditcard.csv` from the link above and
place it locally at:

```text
data/creditcard.csv
```

Expected features:

```text
Time, V1, V2, ..., V28, Amount
```

Target:

```text
Class
```

### Data Leakage Prevention

The workflow is:

```text
Raw Data
   ↓
Stratified Train/Test Split
   ↓
Training Set
   ↓
Cross Validation / Model Selection / Threshold Selection
   ↓
Freeze Configuration
   ↓
Final Test Evaluation
```

The final test set is not used for:

- scaler fitting,
- cross-validation,
- model selection,
- hyperparameter selection,
- threshold tuning.

For Logistic Regression and KNN, `StandardScaler` is inside the Scikit-learn
Pipeline during CV. For PyTorch, a new `StandardScaler` is fitted only on the
training portion of each CV fold.

## 3. Initial Hypothesis

Before running the experiments:

1. Logistic Regression should provide a strong linear baseline.
2. KNN should be sensitive to feature scaling because it relies on distance.
3. Decision Tree should learn nonlinear rules but may overfit as depth grows.
4. Recall should be important because False Negatives are missed fraud.
5. Recall alone should not be maximized because excessive False Positives create
   false alarms.
6. Predicting every transaction as legitimate can still produce high Accuracy
   on a severely imbalanced dataset while Fraud Recall is extremely poor.
7. The PyTorch MLP may capture nonlinear relationships but can also introduce
   additional overfitting and optimization risk.

## 4. Model Comparison

### Model 1 — Logistic Regression

Purpose:

- establish a simple binary-classification baseline,
- study a linear classifier on imbalanced data.

### Model 2 — KNN

Purpose:

- analyze distance-based learning,
- study the effect of feature scaling.

### Model 3 — Decision Tree

Purpose:

- learn nonlinear decision boundaries,
- analyze overfitting,
- investigate class-imbalance behavior.

### Model 4 Bonus — PyTorch MLP

All neural-network code is implemented with **PyTorch**.

```text
30 inputs
  ↓
Linear(30, 64)
  ↓
ReLU
  ↓
Dropout(0.20)
  ↓
Linear(64, 32)
  ↓
ReLU
  ↓
Dropout(0.20)
  ↓
Linear(32, 1)
  ↓
Raw Logit
```

Training configuration:

- loss: `BCEWithLogitsLoss`,
- imbalance handling: `pos_weight = negatives / positives`,
- optimizer: Adam,
- probability: `sigmoid(logit)`,
- scaling fitted independently inside every CV training fold.

### Metrics

Every implemented model reports:

- Accuracy
- Precision
- Recall
- F1-score
- Confusion Matrix
- FP
- FN

### Cross Validation

The project uses:

```text
5-Fold Stratified Cross Validation
```

It reports the required Mean Precision, Mean Recall, and Mean F1, plus:

- F1 standard deviation,
- Train F1,
- Generalization Gap.

Model comparison is performed from training out-of-fold predictions, not from
the final test set.

## 12. Reflection

### Question 1 — Why is Accuracy misleading?

The legitimate class dominates the dataset. A classifier can label nearly all
transactions legitimate and still obtain high Accuracy while detecting little
or no fraud. Fraud Recall, Precision, F1, and FP/FN must therefore be examined.

### Question 2 — What is the trade-off between detecting more fraud and generating more false alarms?

A lower threshold generally predicts more transactions as fraud. This can
reduce FN and improve Recall, but it can also increase FP and false alarms. The
project measures the actual trade-off from validation probabilities rather
than assuming a business optimum.

### Question 3 — What would be improved with one additional week?

Priorities:

- Precision–Recall curve and PR-AUC,
- detailed FP/FN error analysis,
- explicit business-cost threshold optimization,
- probability calibration,
- time-aware validation,
- drift monitoring,
- stronger ensemble baselines,
- additional leakage-safe imbalance strategies,
- PyTorch MLP hyperparameter tuning and early stopping.
